Each cell runs `tests/integration/TakeoverRestTest.php` and `tests/integration/takeover-rest-http.sh` on the store that `TakeoverCliTest.php` has taken through two switch cycles. A takeover HTTP mu-plugin answers both probes, so there is no provider traffic. Each Action Scheduler tick runs in a fresh process, as a real queue run would. Verified:

- **Auth:** every route needs `manage_woocommerce`. Every write also needs the explicit `wp_rest` nonce. Over real HTTP, an Application Password alone is refused with 403 `supcheckout_nonce_invalid`.

- **Async driver:** a switch, rollback, checks and finalize run through Action Scheduler. The rollback really waited out its 120 s settle barrier as a scheduled resume, not a sleeping request.

- **Self-test:** exactly one read-only availability probe, in test and live mode alike.

### On-the-wire notes
- Our responses send `Cache-Control: no-store, private`. For a logged-in user, WordPress core's `nocache_headers()` value replaces ours; it still contains `no-store` and `private`.
- A logged-out `?_envelope` request gets no `Cache-Control` header. Its body is only the generic 401.
- The Action Scheduler admin "Run" row action calls `process_action()` directly and bypasses the lazy hook registration. That action is marked failed, nothing advances, and the next status poll's watchdog queues a new one.
- An abort while a switch is running returns 409 `supcheckout_state` from the plan gate. The single-flight 409 `supcheckout_operation_in_progress` applies when the other kind's plan passes.
- WP-Cron (or a system cron, or admin page loads) is required. Otherwise `GET /onboarding/status` reports `runner.stalled: true` after 60 s past due.

## Independent security review
**Method.** A manual source review of the 0c surface on this branch. It covers `git diff f228915...HEAD -- src` plus the Task 1–2 files already on `main`: `src/Rest/*`, `src/Takeover/Onboarding/*`, `src/Takeover/CachePurger.php`, `src/Takeover/BudgetedSystem.php`, the `PausedBoot`, `Plugin`, `Preflight`, `Rollback` and `Finalize` changes, and `WordPressCutoverSystem::deactivate_plugin()`. It follows the brief's focus list and the WordPress security checklist (capability, nonce, input validation, output bounding, secrets, races, fatal paths). The reviewer did not write the 0c code. The plan names the `ecc:security-reviewer` agent; this closeout ran without sub-agents, so the review was done by hand against the same focus list.

**Result: no Critical and no High finding.** The one Medium (#10) is fixed on this branch.

| # | Focus | Finding | Severity | Disposition |
|---|---|---|---|---|
| 1 | REST auth, nonce, capability | All 12 routes use `RequestGuard::can_manage` as `permission_callback` (no `__return_true`, none missing). `Routes::guard()` at `rest_request_before_callbacks` repeats the capability check and, on writes, the nonce and unknown-parameter checks before core's schema error, so a caller without the capability learns nothing about the arguments. The controllers repeat steps 2–3 in case another plugin removes the filter. 401 for logged out and 403 for logged in, via `rest_authorization_required_code()`. The namespace index is guarded too. | — | Verified. |
| 2 | CSRF on every write | Every non-GET/HEAD method counts as a write (fail closed). `check_write()` verifies `X-WP-Nonce` against `wp_rest` explicitly; `_wpnonce` alone is not accepted. A `?_method=GET` override on a POST turns it into a read of the status. An Application Password cannot obtain a REST nonce: `admin-ajax.php?action=rest-nonce` needs cookie auth. | — | Verified; the over-HTTP 403 is certified (run 39177850394). |
| 3 | Unknown parameters and consent | JSON, body and query keys outside the route's args and core's reserved keys give a 400 error. The reported key list is bounded (20 names, 100 characters each). Consent flags are booleans defaulting to `false`, read as `=== true`. `Operation::consent()` stores only the three known keys, each strictly true. Finalize needs the exact word `FINALIZE` unless `dry_run`. | — | Verified. |
| 4 | Rate limiting and races | Buckets are per site, created by insert-if-absent and advanced by compare-and-swap on the stored closing time, so a race allows exactly one request. `Operation::start()` is compare-and-swap single-flight. An unreadable bucket or record fails closed. | — | Verified. |
| 4a | Rate limiting | One manager's write closes the bucket for every manager (10 s; 65 s for the shared provider-probe bucket), and a start refused by its plan, for example a self-test on an unswitched store, still spends the slot. | Low | Accepted: per-site is deliberate, so the shared provider rate gate and single flight hold whoever clicks. `Retry-After` tells the caller when to retry. |

| 7 | Minimal paused surface | Paused, only `rest_api_init` → `Routes::register_takeover` (8 routes) is added, plus the two driver hooks: at once under cron, AJAX or WP-CLI, otherwise lazily on `action_scheduler_before_process_queue`. No state is read, no gateway, Blocks method, WC-API route, payment or subscription cron hook or global symbol. `PausedBootTest` and the public-surface snapshot pin it. | — | Verified. |
| 7a | Paused surface | The Action Scheduler admin "Run" row action bypasses the lazy hook, so that action fails without effect. | Info | Accepted; the watchdog re-queues it (certified). |
| 8 | Driver crash, retry and attempt bounds | Long phases store the attempt before the work starts: at most 3 entries (`MAX_LONG_ATTEMPTS`), then `driver_exhausted` with a WP-CLI hint. Busy store: 17 retries 60 s apart. Provider cooldown: 3 retries 65 s apart (self-test: 1). A dead-man watchdog fires at `Quiesce::TTL` + 60 s for long phases and 300 s for short ones.
